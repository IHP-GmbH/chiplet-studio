# Tests that MUST be present and pass in a complete gate run.
#
# Set identity between the ctest inventory and the JUnit report says the run was
# complete with respect to itself. It cannot say the build registered the tests
# it should have: a file never added to a CMakeLists is absent from both and
# reconciles perfectly. These are the names whose absence has actually happened,
# or would cost the most.
#
# AtomicSave.FailedSaveLeavesTheOriginalIntact and
# AtomicSave.PreservesTheModeOfTheFileItReplaces are the reason this list exists.
# They skip on geteuid()==0, so a gate run as root certified save safety without
# running the tests for it, for months, while reporting them as known
# display-only skips.
#
# The names below come from two places and no count is written down anywhere in
# this file, deliberately: a total is a second thing to keep true, and the next
# addition falsifies it silently.
#
# The save-safety set is the 12 this file first carried plus the Save,
# recovery and checkpoint cases that came with whole-document capture.
#
# The validated-import set is every case the validated import added: the
# SaveFailureKind family, the rejected-output policy pair, the hostile-input
# cases and the import write policy. Until they were pinned, the reconciler
# could not notice any of them going missing, because presence is checked
# against this list and a name that was never here is absent from both artifacts
# and reconciles perfectly. That is the same hole the header above describes,
# reopened by every test it added.
#
# How those names were derived, because the obvious way is wrong. Diffing the
# TEST() macros between the two trees gives a candidate list; that list was then
# cross-checked against the ctest inventory in an actual run, and the check
# earned its place: GdsLoading.KLayoutNotAvailable is a TEST() in the sources
# that does NOT register when KLayout is available, so a grep-only list would
# have pinned a name that cannot appear and turned the gate red for a reason
# having nothing to do with the change. Pin what an inventory says exists, never
# what a grep says is written.
#
# The import-refusal set is three cases, here because the property they
# hold is one nothing else in the suite would notice losing: a spec the import
# cannot describe is refused, and the refusal is not then answered by writing
# the document into the fallback directory anyway.
# ARefusedSpecIsNotRescuedByTheFallback is the one worth naming. Every other
# assertion about a refusal would also pass for a guard that ran later, after
# destination admission; that one would not, because reaching admission on an
# unwritable destination produces DestinationIo and DestinationIo is what routes
# to the fallback.
